۱. چشم‌انداز محصول

قاصدک یک پلتفرم SaaS فارسی‌محور برای اتوماسیون مکالمه و تعامل در شبکه‌های اجتماعی است که کار خود را از اینستاگرام آغاز می‌کند. کسب‌وکار باید بتواند حساب حرفه‌ای واجدشرایط خود را با روش رسمی متا متصل کند، تعامل‌های پشتیبانی‌شده را مدیریت کند و برای رویدادهای مجاز پاسخ و فرایند خودکار بسازد؛ بدون آنکه درگیر جزئیات OAuth، توکن، Webhook، retry و محدودیت‌های API شود.

قاصدک برای دور زدن محدودیت‌های متا، اسکرپ کردن اطلاعات خصوصی یا استفاده از رمز عبور اینستاگرام طراحی نمی‌شود. مزیت محصول، قابل‌اعتماد کردن قابلیت‌های رسمی است.

۲. مسئله‌ای که حل می‌کنیم

کسب‌وکارها حجم زیادی از کامنت و دایرکت تکراری دریافت می‌کنند، سرنخ‌ها در ساعات شلوغ از دست می‌روند و پاسخ‌های تکراری نیروی انسانی را مصرف می‌کند. در سوی فنی نیز رخدادهای تکراری Webhook، خطاهای موقت سرویس خارجی، چرخه عمر توکن، محدودیت نرخ و تغییر سیاست پلتفرم چالش‌های جدی هستند. قاصدک این پیچیدگی را پشت یک محصول شفاف و قابل پایش پنهان می‌کند.

۳. کاربران هدف

  • صاحب کسب‌وکار که اینستاگرام کانال فروش یا پشتیبانی اوست.
  • ادمین یا کارشناس شبکه اجتماعی که Inbox، کامنت و سرنخ را مدیریت می‌کند.
  • تیم‌هایی که به Workspace و دسترسی کنترل‌شده نیاز دارند، نه اشتراک رمز عبور.
  • اپراتور قاصدک که برای پشتیبانی و عملیات به مشاهده‌پذیری و دسترسی حسابرسی‌شده نیاز دارد.

۴. اصول محصول

  1. اول API رسمی و رعایت سیاست پلتفرم.
  2. هر اتوماسیون باید قابل توضیح و قابل ردیابی باشد.
  3. تکرار Webhook یا retry نباید اثر ناخواسته تکراری بسازد.
  4. ایزوله‌سازی Workspace در سمت سرور اجباری است.
  5. قابلیت کمتر ولی مطمئن، بهتر از قابلیت زیاد و شکننده است.
  6. طراحی UI در Penpot تأیید می‌شود و سپس به Next.js تبدیل می‌شود.
  7. State پروژه داخل مخزن است تا Agent بعدی به حافظه چت وابسته نباشد.

۵. جهت نسخه MVP

نسخه اولیه شامل هویت و Workspace، اتصال حساب اینستاگرام، دریافت پایدار Webhook، Inbox مکالمات، موتور اتوماسیون با مجموعه محدود و تأییدشده Trigger/Action، Contactهای سبک و رابط مدیریتی Next.js خواهد بود. فهرست دقیق اتوماسیون‌ها عمداً در این اسکلت نهایی نشده و در Milestone اول با مستندات رسمی متا تطبیق داده می‌شود.

۶. موارد خارج از هدف اولیه

  • ورود با رمز اینستاگرام یا اتوماسیون حساب شخصی با روش غیررسمی.
  • ارسال انبوه دایرکت خارج از قوانین پلتفرم.
  • تبدیل شدن به موتور Workflow عمومی و بی‌ارتباط با مسئله محصول.
  • شروع با Microservice بدون نیاز واقعی.
  • پشتیبانی هم‌زمان از همه شبکه‌های اجتماعی پیش از پایدار شدن هسته اینستاگرام.

۷. معیارهای موفقیت

موفقیت مهندسی با پایداری دریافت رخداد، نرخ بسیار پایین اثر تکراری، تشخیص سلامت اتصال، مشاهده نتیجه اتوماسیون، جداسازی صحیح Workspace، استقرار قابل بازتولید و مجموعه تستی سنجیده می‌شود که تغییرات Agentهای متعدد نتوانند بی‌صدا رفتار اصلی را خراب کنند.

۹. ریسک‌های مهم

وابستگی به API و سیاست متا، تغییر permission و review، Webhook تکراری یا خارج از ترتیب، افشای توکن، IDOR بین Workspaceها، اثر چندباره اتوماسیون، طراحی UI تولیدشده و رانش معماری میان Agentها مهم‌ترین ریسک‌های اولیه‌اند. برنامه Milestoneها عمداً ابتدا این ریسک‌ها را کنترل می‌کند.
