۱. هدف تحلیل

این سند میان Vision و Design قرار می‌گیرد و قبل از تصمیم‌های پیاده‌سازی، مرز مسئله را روشن می‌کند. تمرکز روی capabilityهای کسب‌وکار، شکست‌های واقعی، concurrency و سؤال‌های باز است، نه روی نام کلاس‌ها و کتابخانه‌ها.

۳. تحلیل اتصال حساب

مسیر مطلوب: عضو مجاز → ساخت state/correlation محافظت‌شده → OAuth متا → callback → اعتبارسنجی state → دریافت داده/توکن لازم → ذخیره امن → بررسی subscription/capability → نمایش health بدون token. خطاهای denial، state دستکاری‌شده، permission ناقص، نوع حساب نامناسب، callback تکراری و revoke باید state قابل بازیابی بسازند.

۴. تحلیل Webhook

ورودی Webhook باید کوتاه و مقاوم باشد: authenticity را بررسی کند، delivery را شناسایی/ثبت کند، داده لازم را پایدار کند و در زمان مناسب acknowledge دهد. منطق طولانی اتوماسیون نباید پاسخ Webhook را شکننده کند. duplicate و out-of-order شرایط عادی سیستم خارجی هستند، نه edge case نادر.

۵. تحلیل اجرای اتوماسیون

رخداد نرمال‌شده Workspace/Account را مشخص می‌کند؛ نسخه‌های فعال سازگار انتخاب می‌شوند؛ شرط‌ها deterministic ارزیابی می‌شوند؛ execution/effect identity ساخته می‌شود و Action از port مناسب اجرا می‌گردد. نتیجه باید transient، permanent/policy و success را از هم تفکیک کند.

۶. Consistency و Concurrency

Monolith بودن به معنی حذف distributed behavior نیست؛ Meta و شبکه بیرونی‌اند. ورودی at-least-once است و commit PostgreSQL با API خارجی اتمیک نیست. Inbox/Outbox/Effect ledger در Milestone مربوط باید دقیق طراحی شود. نسخه Automation باید immutable یا قابل ارجاع باشد تا ویرایش جدید معنی اجرای درحال انجام را تغییر ندهد.

۷. تحلیل امنیت

تهدیدهای اصلی: سرقت token، OAuth state جعلی، Webhook جعل/replay، IDOR بین Workspaceها، افزایش سطح دسترسی، نشت در log، abuse اتوماسیون و misuse اپراتور. کنترل‌ها شامل secret protection، signature/auth verification، server authorization، audit، rate control و تست امنیتی هستند.

۸. تحلیل شکست

  • قطع PostgreSQL: readiness fail و عدم acknowledge کاری که durable نشده است.
  • خطای موقت Meta: retry محدود با backoff و idempotency.
  • خطای policy/permanent: عدم retry کورکورانه و پیام قابل اقدام.
  • token revoke: connection unhealthy و توقف فراخوانی بیهوده.
  • duplicate event: یک logical effect.
  • خرابی ناشی از Agent: test/CI/state نقش executable memory را دارند.

۹. سؤال‌های باز M01

مسیر دقیق Instagram Login و permissionها، trigger/action مجاز، app review و business verification، شناسه مناسب dedup، retention داده و انتخاب provider احراز هویت/پرداخت باید با اطلاعات جاری و منبع اولیه تثبیت شود. این اسکلت عمداً این موارد را حدس نزده است.
