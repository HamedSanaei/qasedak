۱. Overview — نمای کلی

قاصدک ابتدا بر اساس capability کسب‌وکار تقسیم می‌شود و داخل هر ماژول Clean Architecture دارد. این انتخاب مانع از آن می‌شود که یک Domain/Application/Infrastructure سراسری با رشد پروژه به محل تجمع همه قابلیت‌ها تبدیل شود. API فقط composition/transport root است و Next.js اپلیکیشن مستقل است.

۲. Goals — اهداف

  • locality هر capability و جهت وابستگی قابل enforce.
  • جدایی business rule از ASP.NET، EF، PostgreSQL، Meta و UI.
  • تحمل retry/duplicate و امنیت Workspace.
  • توسعه چند-Agent با Graphify، تست و state versioned.
  • خروجی container قابل بازتولید.

۳. System Context — زمینه سیستم

Business User -> Next.js -> HTTPS API -> ASP.NET Core Meta / Instagram -> OAuth + Webhook -> API API <-> PostgreSQL API <-> Supported Meta APIs Future Payment Provider <-> API

Browser هیچ credential متا دریافت نمی‌کند و payload/provider detail در Infrastructure خاتمه می‌یابد.

۴. High-Level Architecture — معماری سطح بالا

frontend/Qasedak.Web | HTTPS backend/Qasedak.Api +-- Identity +-- Instagram +-- Conversations +-- Automations +-- Contacts +-- Billing Inside each module: Infrastructure --> Application --> Domain

ساختار اولیه Modular Monolith است؛ Microservice تنها با شواهد واقعی مقیاس/مالکیت توجیه می‌شود.

۶. Layer Responsibilities — مسئولیت لایه‌ها

Domain

معنی کسب‌وکار و invariant؛ هیچ وابستگی به HTTP، EF، DB، Meta یا UI.

Application

Orchestration یک use case، portها، authorization requirement و result semantics.

Infrastructure

EF/PostgreSQL، Meta HTTP/OAuth، رمزنگاری و implementation سرویس خارجی.

API

Routing، request/response، middleware، auth wiring، health و DI.

Frontend

Next.js مستقل بر پایه Penpot و API contracts.

۷. Dependency Rules — قوانین وابستگی

Module.Domain -> BuildingBlocks.Domain only Module.Application -> own Domain + Application building blocks Module.Infrastructure -> own Application/Domain + infra building blocks Qasedak.Api -> module Infrastructure projects Qasedak.Web -> HTTP contracts only

reference مستقیم میان دو business module ممنوع است و `scripts/check_architecture.py` این قرارداد را در CI بررسی می‌کند.

۸. Data Architecture — معماری داده

یک PostgreSQL 18 با schemaهای مالکیت‌دار آغاز می‌شود: identity، instagram، conversations، automations، contacts و billing. هر ماژول migration/mapping خود را دارد و table ماژول دیگر مستقیماً query نمی‌شود. UUIDv7 گزینه پیش‌فرض ID داخلی و timestamptz برای instant زمانی است.

۹. Runtime Flows — جریان‌های زمان اجرا

OAuth

Next.js → API use case → Meta adapter → callback → validate → protected persistence → safe health result.

Webhook

Meta → verify → durable dedupe/inbox → acknowledge → normalize → processing.

Automation

normalized event → matching version → deterministic evaluation → idempotent effect → Meta adapter → recorded outcome.

۱۰. Security — امنیت

  • OAuth state و webhook authenticity/replay کنترل شود.
  • Token به frontend برنگردد و at-rest محافظت شود.
  • Workspace authorization سمت سرور.
  • redaction در log و runtime secret injection.
  • rate/abuse control و audit actionهای حساس.
  • CodeQL/dependency scan و security regression test.

۱۱. Deployment — استقرار

دو image مستقل qasedak-api و qasedak-web همراه PostgreSQL در یک Compose application اجرا می‌شوند. container چند-process برای Node + ASP.NET عمداً انتخاب نشده است. imageها immutable و توسط GitHub Actions ساخته می‌شوند.

۱۲. Non-Functional Requirements — نیازمندی‌های غیرعملکردی

Reliability با semantics ضد duplicate، Maintainability با module locality، Testability با Domain خالص و Testcontainers، Observability با correlation/telemetry، Recoverability با backup/restore، Security با tenant isolation و UI Accessibility با هدف WCAG 2.2 AA کنترل می‌شود. عدد performance پس از اندازه‌گیری workload واقعی تعیین می‌شود.

۱۳. Architecture Constraints — قیود معماری

  1. Modular Monolith تا زمانی که evidence خلافش وجود نداشته باشد.
  2. جهت Clean Architecture داخل ماژول.
  3. عدم global Persistence مشترک.
  4. عدم reference/table access مستقیم بین ماژول‌ها.
  5. Next.js تنها frontend و مستقل از ASP.NET.
  6. PostgreSQL دیتابیس اصلی.
  7. Meta API رسمی؛ عدم scraping/credential bypass.
  8. Penpot مرجع UI.
  9. GitHub Actions + Docker artifact.
  10. Graphify پیش از broad navigation Agent.
  11. State و commit پیشنهادی بعد از هر task.
  12. ممنوعیت تضعیف test gate برای سبز شدن.
