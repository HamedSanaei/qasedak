۱. فلسفه تست

در قاصدک، تست «حافظه اجرایی» پروژه است. چون Agentهای متعدد در چند روز و چند session کد را تغییر می‌دهند، suite باید تغییر رفتار ناخواسته را آشکار کند؛ نه اینکه فقط درصد coverage زیبایی نشان دهد. feature بدون failure path و regression مناسب کامل نیست.

۳. قانون Regression

هر Bug تأییدشده باید تا حد معقول یک تست داشته باشد که بدون Fix fail شود. Agent حق ندارد برای سبز شدن CI assertion را ضعیف، test را skip، warning را suppress یا gate را پایین بیاورد مگر با تأیید صریح انسان و ثبت دلیل.

۴. سناریوهای بحرانی اجباری

  • دسترسی به resource Workspace دیگر با ID حدس‌زده شده رد شود.
  • OAuth state tamper/replay/denial کنترل شود.
  • Token در response/log نشت نکند و revoke رفتار امن بسازد.
  • Webhook جعلی رد و duplicate چندباره یک logical effect ایجاد کند.
  • concurrent duplicate execution اثر مضاعف ندهد.
  • Automation بدون Trigger/Action معتبر فعال نشود.
  • شرط‌ها edge caseهای متن/داده را deterministic ارزیابی کنند.
  • Meta success/transient/permanent/timeout تفکیک شود.
  • Retry بعد از نتیجه مبهم blind duplicate نسازد.
  • Payment webhook replay در آینده subscription را دوباره اعمال نکند.

۵. Coverage و Mutation

Coverage ابزار تشخیص است. پس از شکل گرفتن کد معنادار، برای Domainهای بحرانی حدود ۹۰٪ توجه line/branch و برای Application حدود ۸۰٪ هدف راهنماست، نه عدد مقدس. M10 روی قواعد حساس mutation testing (مثلاً Stryker.NET) اضافه می‌کند تا ضعف assertionها مشخص شود.

۶. Performance و Reliability

پیش از release، workload نماینده برای webhook ingress، query Inbox و automation evaluation با cardinality واقعی و duplicate/retry pattern اجرا می‌شود. failure provider، اختلال PostgreSQL و retry worker نیز در حد معماری runtime آزموده می‌شوند. عدد latency از اندازه‌گیری به‌دست می‌آید نه از حدس scaffold.

۷. Security Testing

CodeQL و dependency scan baseline هستند. تست targeted برای IDOR/authorization، authenticity/replay، rate abuse، redaction و input خراب اضافه می‌شود. scanner جای threat review را برای بخش‌های پرریسک نمی‌گیرد.

۸. CI Gates

PR باید repository contract، architecture، restore/build/test .NET، lint/typecheck/test/build Next.js و Docker build را پاس کند. Release image با provenance/SBOM منتشر می‌شود و CI نباید secret production داشته باشد.

۹. معیار پایان Task

Task فقط وقتی DONE است که acceptance behavior در سطح مناسب تست شده، suite سبز باشد، skip/suppression جدید توضیح‌نشده وجود نداشته باشد، Graphify evidence و state/docs/manifest به‌روز باشند و gate اجرا نشده دقیقاً با دلیل گزارش شود. دستورات استاندارد handoff عبارت‌اند از scripts/agent_finalize.py و scripts/verify.py --full.
