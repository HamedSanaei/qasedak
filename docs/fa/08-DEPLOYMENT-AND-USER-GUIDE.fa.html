۱. وضعیت سند

این نسخه قرارداد پایه deployment و user flow اولیه است. تا پایان M10/M11، جزئیات production مانند migration sequencing، backup، TLS، observability و rollback پس از تمرین عملی نهایی محسوب نمی‌شوند.

۲. اجزای Runtime

  • qasedak-api: ASP.NET Core روی port داخلی 8080.
  • qasedak-web: Next.js standalone روی port داخلی 3000.
  • PostgreSQL 18: state پایدار.
  • Worker/Queue آینده فقط با task/ADR در M04/M06 اضافه می‌شود.

Backend و Frontend imageهای جدا هستند ولی با یک Compose stack بالا می‌آیند.

۳. اجرای محلی Docker

cp .env.example .env docker compose up --build

Web در localhost:3000، API scaffold در localhost:8080/api/v1/system و liveness در localhost:8080/health/live در دسترس خواهد بود. رمز نمونه فقط برای local است.

۴. توسعه مستقیم و Graphify

Backend به .NET 10 SDK و Frontend به Node.js 22+ نیاز دارد. PostgreSQL می‌تواند با Compose اجرا شود. قبل از broad navigation توسط Agent، Graphify طبق `AGENTS.md` باید initialize شود. M00-004 lockfile و restore/build واقعی را تثبیت می‌کند.

۵. CI/CD

Workflow اصلی repository contract، .NET build/test، Next.js lint/typecheck/test/build و Docker build را اجرا می‌کند. CodeQL و Dependabot نیز فعال‌اند. Workflow image در tag نسخه یا اجرای دستی، API و Web را به GHCR با provenance/SBOM منتشر می‌کند.

۶. پیکربندی Production

DB credential، connection string، public originها، secretهای auth، Meta و providerهای آینده از secret facility تزریق می‌شوند و در repo/image قرار نمی‌گیرند. Reverse proxy/ingress در M11 TLS و public routing را فراهم می‌کند و PostgreSQL معمولاً public نمی‌شود.

۷. Persistence PostgreSQL 18

Image رسمی PostgreSQL 18 داده version-specific را زیر /var/lib/postgresql/18/docker نگه می‌دارد و parent /var/lib/postgresql را VOLUME اعلام می‌کند؛ Compose قاصدک همان parent را mount می‌کند. تغییر مسیر volume در major upgrade بدون plan مجاز نیست.

۸. Migration و Deploy Sequence

فرایند production باید مشابه این باشد: بررسی image/config → backup/check → migration کنترل‌شده → update API/Web → readiness/smoke → مشاهده telemetry → finalize یا rollback. replicaهای مختلف نباید migration destructive را مستقل race کنند.

۹. Health، Backup و Rollback

Endpointهای `/health/live` و `/health/ready` وجود دارند و dependency check واقعی با پیاده‌سازی persistence افزوده می‌شود. M10 restore در محیط پاک + smoke test را تمرین می‌کند. image tag immutable است اما rollback دیتابیس باید برای هر migration جدا تحلیل شود.

۱۰. راهنمای اولیه کاربر

  1. ورود و انتخاب/ساخت Workspace.
  2. رفتن به تنظیمات Instagram و شروع اتصال رسمی Meta.
  3. بررسی health و permissionها.
  4. مشاهده interactionهای پشتیبانی‌شده در Inbox.
  5. ساخت Automation از Trigger/Condition/Action مجاز.
  6. Validate و Activate و مشاهده execution result.
  7. Disable Automation یا Disconnect Account در صورت نیاز.
قاصدک هرگز برای اتوماسیون رسمی از کاربر رمز عبور Instagram درخواست نمی‌کند.

۱۱. چک‌لیست پیش از Launch

Milestoneهای لازم سبز، Meta review/capability جاری، secretها امن، backup/restore تست‌شده، migration تمرین‌شده، TLS/domain آماده، rate control فعال، alert/telemetry معتبر، privacy/retention ثبت‌شده، rollback تمرین‌شده و flowهای حیاتی Penpot/Next.js از نظر responsive و accessibility تأیید شده باشند. state پروژه باید به commit/tag/image همان release اشاره کند.
